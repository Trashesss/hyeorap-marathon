# 0001. 계산과 화면을 가른다

- 상태: 적용됨
- 날짜: 2026-10-09
- 정한 사람: @cbnuleehyunwoo

## 배경

게임은 HTML 한 장, 약 3,200줄로 시작했습니다. 규칙을 다루는 코드가 three.js의 물체를 직접 옮기고 화면 구석의 글자를 직접 고쳤습니다. 목표는 다른 사람과의 온라인 대전인데, 이 상태로는 판의 계산을 브라우저 밖에서 돌릴 수 없었습니다.

## 검토한 안

- **가. 한 파일 유지.** 서버를 만들 때 규칙을 서버용으로 한 번 더 쓴다.
- **나. 계산과 화면을 가른다.** 계산은 상태와 사건만 내놓고, 화면은 그것을 읽어 그린다.

## 결정

**나**를 골랐습니다.

- 계산을 서버가 하든 방장의 브라우저가 하든, 가르는 일은 먼저 해야 합니다. 다른 사람의 화면은 받은 상태만으로 그려야 하기 때문입니다.
- 가르고 나면 같은 코드를 서버에서 그대로 돌릴 수 있습니다. **가**는 규칙이 두 벌이 되어 서로 어긋납니다.
- 가르는 일 자체는 서버 없이 할 수 있고, 끝난 뒤에도 게임이 똑같이 동작하는지 확인할 수 있습니다.

경계는 이렇게 정했습니다.

- `src/sim/`은 브라우저 기능과 three.js를 쓰지 않습니다.
- 한 번 보여주고 끝나는 것(팝업, 알림, 휘두른 자국)은 사건으로 내보냅니다. 사건에는 숫자와 글자만 담습니다.
- 난수는 밖에서 넘겨받습니다. 같은 씨앗과 같은 입력이면 같은 판이 나옵니다.

## 치르는 값

- 파일이 여러 개가 되어, 한 장짜리 페이지가 필요하면 `npm run build`로 묶어야 합니다.
- 상태 안에서 선수끼리 서로를 직접 가리키는 곳(`grudge`, `carriedBy`, `owner`, `carrier` 등)이 남아 있습니다. 네트워크로 보내려면 번호로 바꿔야 합니다.
- 화면 쪽 코드는 아직 전역 `THREE`에 기대고 있습니다. [0008](0008-three-from-cdn.md) 참고.

## 다시 볼 조건

온라인 대전을 포기하고 혼자 하는 게임으로 남기기로 한다면 이 경계를 엄격히 지킬 이유가 줄어듭니다.

## 근거

- `npm test`가 `src/sim/`만으로 Node에서 여러 판을 끝까지 돌립니다. 경계를 넘으면 "계산 모듈은 브라우저와 three.js에 기대지 않는다" 시험이 실패합니다.
- 가른 뒤 `npm run test:e2e`로 메뉴부터 판이 끝날 때까지 이전과 같게 동작하는 것을 확인했습니다.
